# Systematic checks

The user cannot be the only detector. Run these before sending a video; they find mechanical problems, not taste problems.

| Check | How | Fail means |
|---|---|---|
| Clip onset | peak of first 20 ms ≤ −38 dBFS | first syllable clipped (audible "loss of audio") |
| Trailing noise | last silence ends ≥ 0.05 s before the file end | stray click/breath |
| Listen-back | Whisper `word_timestamps`, compare to the script by chunk (difflib ≥ 0.45) | wrong reading, swallowed words. English method names transcribe badly: expect false flags |
| Long internal silence | > 1.3 s inside a clip | stalled generation (ordinary sentence gaps are ~1 s) |
| Video joins | changed pixels ±3 frames around each join | visible cut |
| Mix | render narration-only and music-only stems; final − (n + m) per 0.5 s | dropouts, wrong levels (mono downmix lowers the level by 3 dB uniformly: not a bug) |
| Music joins | stem envelope around crossfades and the ending | dips, bumps, abrupt end |

`tools/qa_narration.py` implements the clip checks and writes `qa_report.md`. When the user gives a timestamp, find the scene in `edl.json` and re-run the checks on that scene, then look at the actual audio window rather than guessing.

## Reporting

State what you verified and what you did not. Never write "sounds right" about something you could only measure.
